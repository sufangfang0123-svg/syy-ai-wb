# 新品投前决策引擎｜双站改版与验收说明

> 历史设计记录：本文描述早期双站原型。当前实际能力边界以 `README.md` 和 `docs/phase-1a0-implementation-baseline.md` 为准；公开构建只提供展示站与模拟研究实验室。

## 1. 现状诊断摘要

1. 展示叙事与企业操作混用同一导航，新用户不知道先做什么。
2. 主流程从“信号”和“创意”开始，没有从真实的下一笔投入开始。
3. 原“三分钟演示”是跨页讲解，不是围绕真实任务的上手流程。
4. 五道Gate存在展示，但没有形成一张面向负责人的投前决策单。
5. 错误代价、证据缺口与下一验证之间缺少明确排序关系。
6. 数字实验、真人校准、样品验证和销售回填虽有免责声明，但没有统一独立计数。
7. 棉品基因容易被理解为核心系统永久限定，而不是行业能力包。
8. 快速版、团队版和企业版缺少同一引擎下的功能深度说明。
9. 真实项目与模拟项目缺少明确的工作空间切换与独立存储键。
10. 结果回流尚未成为主导航中的正式步骤。

## 2. 新版产品定位

- 母平台：Evolution Lab／爆款进化舱。
- 核心能力：新品投前决策与下一证据引擎。
- 核心机制：Next-Dollar Gate｜下一笔钱闸门。
- 首个行业包：棉生万物·棉品新品验证包。
- 首批客户：反复开发消费品、即将支付不可逆费用的成长型品牌、ODM/OEM、跨境品牌与区域消费品团队。
- 一句话价值：在下一笔钱花出去之前，找出最危险的假设，并推荐最便宜、最能改变决策的验证。

## 4. 双网站新信息架构

### 展示站

`首页 → 工作原理 → 棉品模拟案例 → 三档版本 → 进入企业工作台`

### 企业产品站

`决策项目 → 证据库 → 风险假设 → 下一验证 → 投前决策单 → 结果回流`

保留的研究实验室：信号、机会、产品进化、数字压力测试、内容实验。它们服务于主闭环，不再充当终点。

### 数据关系

```text
DecisionProject
  ├─ DecisionEvidence[]
  ├─ CriticalAssumption[] ── evidenceIds[]
  ├─ NextBestTest[] ── assumptionId
  ├─ PreInvestmentDecision ── evidenceIds[] + testId
  └─ ResultFeedback[] ── human / sample / sales
```

## 5. 核心用户流程

1. 填写新品、目标人群、阶段、下一动作和预算。
2. 导入证据并记录证据等级、范围和限制。
3. 将需求、产品、成本、供应链等假设按错误代价和缺口排序。
4. 推荐一项最低成本实验，锁定唯一主变量、基准和控制条件。
5. 输出继续、补证或停止，并说明置信限制。
6. 负责人作出人工决定。
7. 回填真人、样品或销售结果。
8. 比较预测与现实偏差，进入规则校准或失败复用。

## 7. 关键页面逐页说明

| 页面 | 目的 | 核心字段/状态 | 关键交互 | 验收 |
| --- | --- | --- | --- | --- |
| 展示首页 | 一句话说明价值 | 下一投入、危险假设、验证预算 | CTA进入工作台 | 不承诺成功率 |

## 8. 新手指引完整方案

- 首次进入企业站自动触发，状态保存在当前工作空间。
- 五步分别定位：项目、证据、风险、实验、决策单。
- 可上一步、下一步、跳过、关闭、重开和重置。
- 模拟数据始终显示“模拟数据空间”，清空前二次确认。
- 真实项目使用独立localStorage键，不受清空演示数据影响。
- 快速版使用通俗解释；团队/企业深度在使用深度选择中说明。
- 当前静态MVP不含账户登录，因此“重新登录”状态需在后端版本验收。

## 9. 100次数字实验规范与数据结构

实验对象至少包含：`id、projectId、assumptionId、hypothesis、primaryVariable、baseline、controls、budget、duration、sample、passThreshold、supplementThreshold、stopThreshold、status、evidenceLevel、isDigital`。

反重复规则：只有假设、主变量、基准、控制条件、目标人群、情景或阈值发生实质变化才计为新实验。数字实验、真人校准、样品验证、销售回填和规则修正分别计数。

## 10. 投前决策单字段框架

已实现：项目ID、阶段、决策日期、下一投入、系统建议、置信程度与限制、危险假设、错误代价、证据ID、下一实验、预算、周期、样本、三类阈值、规则版本、模型版本、负责人、人工决定和结果回流入口。

示例结论：**先补证**。理由是1.8万元包装打样会固化错误价格带，而1200元真人概念选择可先验证按日组合与便携溢价。

## 11. 三档版本与商业模式

| 版本 | 用户 | 深度 | 商业模式 |
| --- | --- | --- | --- |
| 快速版 | 小微品牌、卖家、创业团队 | 单项目、单风险、单实验、单决策单 | 按次/项目/轻订阅 |

## 12. 真实性与风险检查清单

- 不展示客户、收入、订单、样本或节省金额等虚构成果。
- 不输出爆款概率或伪精确成功率。
- D级合成结果不称为真人验证。
- 公开互动不称为购买意愿。
- 规划功能标注“规划”，不可用按钮禁用。
- 证据不足显示“不足以判断”。
- 模拟数据、真实草稿和未来企业能力分区说明。
- Claim、健康、法规和安全只提示风险，不替代专业审核。

## 13. 验证指标、埋点与首轮测试

建议事件：`project_created、evidence_added、assumption_viewed、test_accepted、decision_opened、human_decision_recorded、result_added、guide_started、guide_completed、demo_cleared`。

首轮5—8个团队测试：观察从首次进入到完成第一张决策单的时间、证据追溯率、实验采纳率、指引完成率、对“数字/真人/样品/销售”的区分准确率。没有真实试点前全部标记为待验证指标。

## 14. 分阶段开发任务与验收

1. 阶段A（本轮）：单项目静态P0闭环；构建、移动端和数据隔离通过。
2. 阶段B：后端项目/证据/实验Repository、登录与权限；多浏览器和账号隔离测试。
3. 阶段C：团队审批、导出、审计不可篡改；角色矩阵和恢复测试。
4. 阶段D：行业包配置、企业规则和API；用第二行业验证可复制性。

## 15. 实际修改、测试与未完成事项

### 本轮实际修改

- 新增决策领域模型、共享模拟数据和独立DecisionProvider。
- 新增六个企业工作台路由和双站导航。
- 新增五步新手指引，删除旧三分钟演示组件。
- 改写展示站、元数据、README和全局样式。

### 验收重点

- `npm run build`与GitHub Pages子路径构建。
- 新增路由可静态导出。
- 模拟/真实空间切换、证据新增、结果回填、新手指引、清空演示数据。
- 桌面与手机无关键横向溢出，浏览器无运行时错误。
- 全仓库检索旧“三分钟演示”和伪成功率残留。

### 尚未完成

- 当前为单浏览器静态MVP，没有企业账户、远端数据库、RBAC、不可篡改审计和系统接口。
- 导出按钮明确标注“规划”并禁用。
- 真实项目的假设拆解和实验推荐尚未接入后端规则或模型服务。
- 本轮已补充多视口截图与自动化流程证据；这些证据证明指定主流程和视口通过，不等于完整WCAG合规认证或企业生产验收。

### 2026-08-11 实际验收结果

- `npm run lint`：通过，使用非交互式ESLint CLI并将警告视为失败。
- `npm run typecheck`：通过。
- `npm run test:e2e`：9项通过、5项按桌面/手机项目条件跳过；覆盖五步指引、焦点圈定、Esc关闭、焦点归还、手机视口、人工决定、计数口径和模拟/真实空间隔离。
- `NEXT_PUBLIC_BASE_PATH=/syy-ai-wb npm run build`：通过。构建输出确认13个业务路由；另包含错误页和图标资源，静态生成器共报告17个条目。
- `npm audit --omit=dev --audit-level=high`：通过，0个已知漏洞。
- 五步新手指引：改为目标聚光与自适应浮层；在1366×768第三、四步实测与所有被指向区域重叠面积为0；支持初始焦点、Tab/Shift+Tab圈定、Esc关闭和关闭后焦点归还。
- 人工决定：系统建议保持只读；责任人可独立选择继续投入、先补证或停止，填写理由后持久化，并在与系统建议不一致时保留差异提示。

- 数据隔离：自动化切换模拟与真实草稿空间并分别修改项目内容，确认两套localStorage互不混合。
- 视觉复核：保留1366×768、1440×900、1024×768、390×844、375×667截图；内置浏览器不暴露页面缩放控制，200%项目采用683×384 CSS视口等效检查并明确标注为等效项。
