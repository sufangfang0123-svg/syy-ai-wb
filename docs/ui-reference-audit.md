# UI 参考研究与界面审计

审计日期：2026-08-10（历史视觉基线；产品真实性字段以v0.4.0文档为准）
审计范围：`/`、`/radar/`、`/insights/`、`/opportunities/`、`/evolution/`、`/launch/`、`/content/`  
视口：1440×900、768×1024、390×844、360×800

## 1. 设计目标

本轮采用 **Soft Bio-Tech**：温暖纸张底色、深生物绿、低对比纤维纹理、结构化证据卡与克制动效。视觉服务于“证据 → 机会 → 基因 → 实验 → 门禁 → 真人校准”的因果链，不制造销量预测或确定性结论。

## 4. 主要问题

### 结构问题

1. 需求机会页面缺少实际三栏布局样式，桌面只展示消费信号库；机会与详情落到首屏以下，主任务断裂。
2. 768px 下信号洞察保留两栏网格，但详情跨栏规则造成首屏右侧大面积空白。
3. 产品进化的版本节点没有稳定的横向谱系与状态层，版本、事实状态与变更说明挤成一行。
4. 390/360px 下统计卡全部纵向堆叠，关键信息到达成本过高；虚拟上市五阶段同样形成超长首屏。

### 交互与反馈问题

1. 机会卡在小屏缺少明确详情承载面；用户不知道点选后发生了什么。
2. 创建下一代版本后没有集中反馈“改了哪个基因、哪些下游记录变为stale、门禁状态和下一步人工任务是什么”。
3. 合成数据、真人数据、最终责任人的层级虽然有文字说明，但视觉上没有形成贯穿流程的责任链。
4. 顶部导航只有栏目名，没有明确工作流阶段；移动端展开后当前页状态不突出。

### 视觉与可访问性问题

1. 首页产品基因图是静态散点，缺少可解释的证据、实验、门禁与真人校准关系。
2. 焦点样式不统一，状态变化的 `aria-live` 提示不足。
3. 动效缺少全局 `prefers-reduced-motion` 降级策略。
4. 一些卡片阴影、边界、圆角和内边距层级接近，重要结论与辅助信息区分不足。

## 5. 实施映射

| 问题 | 实施 |
| --- | --- |
| 首页缺少记忆点 | 改造 Orbiting Circles 为“证据/基因/实验/门禁/真人/学习”产品基因核，加入当前幸存物种标签 |
| 数字没有生命感 | 改造 Number Ticker，用于进化漏斗；reduced-motion 时直接显示最终值 |
| 机会工作台断裂 | 桌面恢复三栏；平板/手机点机会后用 Sheet 呈现详情、反证、Gate 与动作 |
| 版本谱系难读 | 横向连接节点，分离版本、事实状态与变更说明；失败谱系保留纵向因果线 |
| 变异后无反馈 | 新增可读状态区，展示改变字段、stale对象、Gate状态与下一步人工任务 |
| 数据责任不清 | 虚拟上市加入“D级合成 → B级真人 → 责任人确认”；内容中枢加入事实/生成/发布三层 |
| 小屏滚动过长 | 统计卡 2×2；实验阶段改为可横向滚动；洞察改为单列；工作台设置明确滚动边界 |
| 动效与焦点 | 统一 `:focus-visible`，增加 `aria-current`、`aria-live` 和 reduced-motion 全局降级 |

## 6. 证据边界

- A–D 证据等级、来源、人工复核、Decision Provenance、五道 Gate、失败谱系、Audit Log 与 DEMO 声明全部保留。
- 公开互动量仍只作为传播信号，不作为购买意愿。
- D级合成结果只用于预筛、压力测试与寻找反例；真人研究和企业责任人仍是高风险决策的必要门槛。
- 审计是基于可见页面与当前前端实现的体验审计，不宣称完整 WCAG 合规。
